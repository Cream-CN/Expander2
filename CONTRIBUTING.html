1. 前排提示

  1. 代码的来源能且只能是与 Unlicense 相兼容的，且必须署名，无论要求与否。
  2. 对于没有许可证的仓库，原则上必须与仓库控制者联系。
  3. 如果你能够自己写代码，可以给写入权限。
  4. 请不要在未阅读完毕文档的情况下贡献。
警告： 不得引入非宽松许可证的库，不得引入链接时依赖。只得使用 .NET 自带类库。不得引入 NuGet 包。

2. 工具链和依赖

  • 使用 Microsoft Visual Studio 2026。
  • C# 项目：Expander_CS，WinForms，输出类型 Windows 应用。
  • F# 项目：Expander_CS.Backend，类库，输出类型 Library。
  • 目标框架以解决方案当前设置为准。
  • 没有额外依赖。
  • F# 项目通过项目引用由 SDK 自动带入 Microsoft.FSharp.Core。
  • 两项目目前引用接口。

3. 命名空间分层

omegay
// C# WinForms UI 层，窗体、菜单、输入、显示、事件分发

Expander_CS.Backend
// F# 类库，算法层
├── Common
// 通用工具：序列解析与格式化
├── Core
// Entry / EntryArena / makeYKey
└── Notation
// 数学记号：每种记号一个独立模块

规则：

  • Common 下只放与具体记号无关的纯工具函数，不得引入 Notation 的依赖。
  • Core 放 Entry、EntryArena、makeYKey 等基础结构，可依赖 Common。
  • Notation 可以依赖 Common / Core，但不得反向依赖。
  • 记号与记号之间不得互相引用，避免耦合。
  • C# UI 层不得直接实现数学展开逻辑，只通过 Backend 模块调用。
  • F# Backend 不得引用 System.Windows.Forms 或 C# UI 项目。
NOTICE： Common 下只放与具体记号无关的纯工具函数，不得引入 Notation 的依赖。Notation 可以依赖 Common / Core，但不得反向依赖。

4. C# / F# 对接约定

  • F# 侧导出的函数使用元组参数，不用柯里化。例如： 
    let expand (seq: int[], term: int) : int[] = ...
    这样在 C# 里调用形式是：XxxNotation.expand(seq, term);
  • 跨边界集合统一用 int[]，避免 FSharpList 在 C# 侧处理繁琐。
  • 返回值避免使用 F# option。跨边界要么返回 null，要么用 bool + out，或者用空数组 / 空字符串表达“无结果”。
  • F# 的 module Foo + let bar 会编译为 C# 的 static class Foo + static method bar。调用形式是 Foo.bar(...)。
  • 项目引用：等 F# 侧接口稳定后，在 Expander_CS 项目上右键 -> 添加 -> 项目引用 -> 勾选 Expander_CS.Backend。然后 C# 里用 using Expander_CS.Backend; 引用。
NOTICE： F# 侧导出的函数使用元组参数，不用柯里化。跨边界集合统一用 int[]。返回值不得使用 F# option。

5. Expander_CS.Backend.Common 接口

5.1 序列解析与格式化 — Sequence.fs

namespace Expander_CS.Backend.Common

module Sequence =
    let parseSequence (text: string) : int[] = ...
    let seqToString (seq: int[]) : string = ...

C# 可见形态：

public static class Sequence
{
    public static int[] parseSequence(string text);
    public static string seqToString(int[] seq);
}

parseSequence 契约：

输入 行为
"" 返回空数组 Array.Empty<int>()
"1,2,3" 返回 { 1, 2, 3 }
"1, ,3" 跳过空 token，返回 { 1, 3 }
" 1 , 2 " 忽略所有空白字符，返回 { 1, 2 }
"abc" int.TryParse 失败被捕获，静默跳过该 token
"1,999999999999" 溢出被捕获，静默跳过

关键约定：

  • 永不抛出异常。所有解析失败均以“跳过该项”处理。
  • 允许前导/尾随逗号，行为等同于空 token。
  • 返回 int[]，F# 中空数组为 [||]，C# 中为 Array.Empty<int>()。
  • 待改进项：当前实现静默丢弃非法输入，UI 层无法向用户报告“第 N 项解析失败”。如需改进，建议新增 parseSequenceEx 返回 (int[], errorList)，保留现有函数作为薄封装。

seqToString 契约：

输入 输出
null 或空数组 "[]"
{ 1 } "1"
{ 1, 2, 3 } "1,2,3"
  • 分隔符固定为半角逗号 ,，无空格。
  • 空序列固定输出 "[]"，而非空字符串，便于 UI 区分“未解析”与“结果为空”。
NOTICE： parseSequence 永不抛出异常。所有解析失败均以“跳过该项”处理。空序列固定输出 "[]"。
警告： 当前实现静默丢弃非法输入，UI 层无法向用户报告“第 N 项解析失败”。如需改进，建议新增 parseSequenceEx 返回 (int[], errorList)，保留现有函数作为薄封装。

5.2 UTF-8 与宽字符转换

原 C++ utf8.hpp 在 C# + F# 项目中不再需要独立接口。

原因：

  • .NET string 本身是 UTF-16。
  • WinForms 控件文本直接使用 string。
  • C# 与 F# 之间传递字符串直接使用 string。
  • 若需要与 UTF-8 字节流交互，使用 System.Text.Encoding.UTF8。

约定：

  • 不新增 CP_ACP 版本。
  • 不在 Expander_CS.Backend 中新增专用 Utf8 模块，除非将来出现明确的字节协议需求。
  • 非法 UTF-8 字节序列行为由 System.Text.Encoding.UTF8 决定。

6. Expander_CS.Backend.Core 接口

6.1 Entry — Entry.fs

C# 可见形态：

public sealed class Entry
{
    public Entry();
    public Entry(int v, int x, int[] y);

    public int Value { get; set; }
    public int X { get; set; }
    public int[] Y { get; set; }
    public ulong YKey { get; }

    public List<Entry> LeftLegUp { get; }
    public Entry? RightLegUp { get; set; }
    public Entry? RightLegDown { get; set; }
    public Entry? LeftLegDown { get; set; }

    public void RefreshKey();

    public static ulong MakeYKey(int[] y);
}

约定：

  • 跨 C# 边界避免 F# option，引用字段用 null。
  • F# 侧类型可加 [<AllowNullLiteral>]。
  • LeftLegUp 在 F# 侧用 ResizeArray<Entry>，C# 侧看到 List<Entry>。
  • 修改 Y 后必须手动调用 RefreshKey()，YKey 不自动刷新。
  • MakeYKey 计算规则与原 C++ 一致，存在碰撞可能。
警告： 修改 Y 后必须手动调用 RefreshKey()，YKey 不自动刷新。跨 C# 边界避免 F# option，引用字段用 null。

6.2 EntryArena — EntryArena.fs

C# 可见形态：

public sealed class EntryArena
{
    public EntryArena();

    public Entry Make();
    public Entry Make(int v, int x, int[] y);
    public Entry MakeEmpty();

    public void Clear();
    public int Size { get; }
}

约定：

  • 原 C++ make(int v = 0, int x = 0, std::vector<int> y = {}) 的默认参数，改为重载，避免 F# option / 可选参数跨 C# 复杂化。
  • EntryArena 统一持有 Entry 生命周期。
  • Clear() 后，之前返回的 Entry 引用全部失效。
  • leg 引用不参与生命周期管理，需自行保证不悬空。
NOTICE： 原 C++ make(int v = 0, int x = 0, std::vector<int> y = {}) 的默认参数，改为重载，避免 F# option / 可选参数跨 C# 复杂化。

7. Expander_CS.Backend.Notation 接口

7.1 记号模块的标准形态

每个记号应位于独立 F# 文件 / 模块中，并在命名空间 Expander_CS.Backend.Notation 下提供统一成员。

F# 侧建议形态：

namespace Expander_CS.Backend.Notation

module XxxNotation =
    [<Literal>]
    let Name = "显示名"

    let definition : string = "定义文本"

    let expand (seq: int[], term: int) : int[] = ...

    let suffix () : string = ...

    // 可选：支持文本展开的记号才提供；不支持时 C# 注册表中留 null。
    let expandText (text: string, term: int) : string = null

C# 可见形态：

public static class XxxNotation
{
    public const string Name = "显示名";
    public static string definition { get; }
    public static int[] expand(int[] seq, int term);
    public static string suffix();
    public static string expandText(string text, int term);
}

成员含义：

成员 类型 含义
Name const string 记号显示名，UTF-8 / .NET string，供 UI 显示
definition string 定义文本，用于下拉框联动显示和独立弹窗
expand(seq, term) int[] -> int -> int[] 对序列 seq 执行 term 项展开，返回结果序列
suffix() unit -> string 追加在结果文本末尾的标记
expandText(text, term) string -> int -> string 可选。文本展开入口，支持 MrSS 这类嵌套表达式

expand 通用约定，所有记号必须遵守：

  • 纯函数：不得修改入参 seq，不得读写全局状态。
  • seq 为空：返回值由具体记号定义；调用方 UI 层有责任先行校验空序列。
  • term < 1：调用方 UI 层有责任先行校验；expand 本身不保证对非法 term 的行为。
  • 异常：expand 不应抛出异常。若记号内部逻辑可能失败，应返回空数组或保持输入不变。
  • 性能：对微型项目不设硬性要求，但应避免 O(n²) 以上的无谓拷贝。

当前 EmptyNotation 的实际契约：

成员 类型 含义
Name const string 记号显示名
definition string 定义文本，暂为占位
expand(seq, term) int[] -> int -> int[] 当前原样返回 seq，忽略 term
suffix() unit -> string 当前返回空串

当前 EmptyNotation 行为：expand 原样返回 seq，suffix() 返回空串。这是占位实现，后续版本将替换。

NOTICE： expand 必须为纯函数，不得修改入参 seq，不得读写全局状态，不应抛出异常。

7.2 C# 侧记号注册表建议

在 Form1.cs 内部定义 NotationInfo：

public sealed class NotationInfo
{
    public string DisplayName { get; init; } = "";
    public string Definition { get; init; } = "";
    public Func<int[], int, int[]>? Expand { get; init; }
    public Func<string>? Suffix { get; init; }
    public Func<string, int, string>? ExpandText { get; init; }
}

注册 EmptyNotation 示例：

new NotationInfo
{
    DisplayName = EmptyNotation.Name,
    Definition = EmptyNotation.definition,
    Expand = EmptyNotation.expand,
    Suffix = EmptyNotation.suffix,
    ExpandText = null // 不支持文本展开
}

7.3 FS / FSalter 语义

UI 层的“移除末项 / 保留末项”按钮，不属于记号接口，而是调用方对展开结果的后处理：

int[] result = EmptyNotation.expand(seq, term);
if (removeLast && result.Length > 1)
{
    Array.Resize(ref result, result.Length - 1);
}

约定：

  • 当 result.Length <= 1 时，FS 操作不执行移除，避免产生空序列歧义。
  • 此策略在 UI 层实现，记号模块不应感知 FS / FSalter 概念。
NOTICE： 当 result.Length <= 1 时，FS 操作不执行移除，避免产生空序列歧义。此策略在 UI 层实现，记号模块不应感知 FS / FSalter 概念。

8. UI 层与记号层的边界

┌─────────────────────────────────────────┐
│ C# WinForms Expander_CS                 │
│ - 读取控件文本                           │
│ - 校验 term >= 1、seq 非空               │
│ - 调用 Sequence.parseSequence            │
│ - 调用 Notation.Xxx.expand / expandText  │
│ - 后处理 FS / FSalter                    │
│ - 追加 suffix                            │
│ - 显示 MessageBox / RichTextBox          │
└──────────────┬──────────────────────────┘
               │ 只通过下列接口通信
               ▼
┌─────────────────────────────────────────┐
│ F# Backend Expander_CS.Backend          │
│ Common: Sequence.parseSequence           │
│         Sequence.seqToString             │
│ Core:   Entry / EntryArena / MakeYKey    │
│ Notation: Xxx.Name / definition /        │
│           expand / suffix / expandText   │
└─────────────────────────────────────────┘

硬性规则：

  • UI 层不得直接操作 int[] 的数学含义，例如自行实现“移除末项”以外的记号逻辑。
  • 记号层不得包含 System.Windows.Forms 或任何 UI 相关引用。
  • 新增记号时，只需在 F# Notation 下增加模块，并在 C# 注册表中增加调用项，不应改动 Common。
警告： UI 层不得直接操作 int[] 的数学含义，例如自行实现“移除末项”以外的记号逻辑。记号层不得包含 System.Windows.Forms 或任何 UI 相关引用。

9. 版本与兼容性

变更类型 要求
新增记号 只增 F# 模块、只增 C# 注册表项，不动现有接口
修改 Common 函数签名 破坏性变更，需同步更新所有调用点与本文档
修改 expand 语义 需在 CONTRIBUTING.md 或 CHANGELOG 中注明
删除任何公开 Notation 成员 不允许，除非同步更新所有调用点与文档

10. 贡献者检查清单

提交涉及接口的 PR 前，请确认：

  • [ ] 新 F# 函数是否使用元组参数，避免 C# 侧拿到柯里化函数？
  • [ ] 跨边界集合是否统一用 int[]？
  • [ ] 返回值是否避免 F# option？
  • [ ] 新函数/成员是否加了必要的文档说明？
  • [ ] Common 是否仍不依赖 Notation？
  • [ ] expand 是否仍为纯函数、不抛异常？
  • [ ] 空序列、term < 1、非法 token 的行为是否与本文档一致？
  • [ ] 若修改了任何签名，是否同步更新了本文档与 C# 调用点？
严重 NOTICE： 提交涉及接口的 PR 前，请确认以上检查清单全部通过。若修改了任何签名，必须同步更新本文档与 C# 调用点。
