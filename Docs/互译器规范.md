# 互译器（Translator）规范

> 文档说明：本文件定义 Expander 中"互译器"功能的语义、接口契约与扩展规则。
> 代码契约见 `Header/notation/translator.hpp`。

## 一、定位与定义

"互译器"是 Expander 中与"展开器（记号）"并列的一类功能：它把某一种记号
（源记号 `source`）的合法表达式文本，映射为另一种记号（目标记号 `target`）中表示
同一序数的表达式文本。

它与展开器的区别：

- 展开器把表达式展开为更小（按基本列/基本序列）的表达式，产出仍是"同一种
  记号"；
- 互译器在两种记号之间转换写法，不改变所表达的序数（"保持序数意义"），
  是"翻译"而非"展开"。

一个互译器对应一个"源记号 → 目标记号"的**有向**映射。互译一般不可逆（或两个
方向需要分别实现），因此 `A→B` 与 `B→A` 视为两个不同的互译器。`source` 与
`target` 相同表示"不改写"，仅用于占位 / 调试 / 框架基线。

## 二、接口契约

互译函数签名（规定，不可更改）：

```cpp
using TranslateFn = std::string (*)(std::string_view);
```

语义：

- 输入：源记号的表达式文本，UTF-8；
- 输出：目标记号的表达式文本，UTF-8；
- 返回的普通文本是"翻译结果"，不会被当作合法表达式提交给展开器（错误文本
  亦然），只展示给用户。

硬性要求（新增互译器必须满足）：

1. **纯函数**：无副作用、无全局可变状态、不访问外部 IO；同一输入必然得到同一
   输出。互译器不应修改任何全局/静态可写数据。
2. **不得抛异常**：任何输入（包括空白、乱码、超长、非本记号文本）都不得抛出
   异常或触发未定义行为；解析失败应返回错误文本（见下）。
3. **输入不变**：不得修改入参 `string_view` 指向的内容。
4. **可重复调用**：同一实例可被反复调用，调用之间不得残留状态。

## 三、互译器条目

互译器表使用 `Header/notation/translator.hpp` 中定义的 `Translator` 结构登记：

```cpp
struct Translator {
    const wchar_t* display_name;  // 展示名（UI 下拉框显示）
    const char*    id;            // 唯一英文 id，稳定引用 / 调试
    const wchar_t* source;        // 源记号名（人类可读）
    const wchar_t* target;        // 目标记号名（人类可读）
    const wchar_t* description;   // 一句话说明（展示在互译器页面）
    TranslateFn    translate;     // 互译函数（必填，不得为空）
};
```

字段约定：

- `display_name` 与 `id` 一一对应，`id` 全局唯一、用英文小写与连字符
  （如 `"identity"`、`"bms-to-upms"`）；
- `source` / `target` 用该记号的常见名（如 `"BMS v4"`、`"UPMS"`、`"任意"`）；
- `description` 一句话说明用途、覆盖范围与限制，避免过长的段落。

## 四、错误处理约定

互译失败时，互译函数应返回下列常量之一（`Header/notation/translator.hpp` 定义），
或带有 `"互译失败："` 前缀的可读说明文本。UI 会原样展示并据此前缀提示"互译
失败"，不会把它当作合法表达式。

| 常量 | 值 |
| --- | --- |
| `kParseError` | `"互译失败：无法解析输入"` |
| `kRangeError` | `"互译失败：输入超出该互译器的适用范围"` |
| `kNotSupported` | `"互译失败：该表达式暂不支持互译"` |

约定：

- 解析失败用 `kParseError`；
- 输入合法但超出该互译器声称覆盖的范围用 `kRangeError`；
- 语义上无法互译（目标记号没有对应表示）用 `kNotSupported`；
- 需要更具体说明时，返回带 `"互译失败："` 前缀的自定义文本（UTF-8）。
- 错误文本与正常输出共用同一通道（函数返回值），不得通过异常或额外通道
  上报错误。

## 五、登记流程

新增一个互译器需要同步修改：

1. `Header/notation/translator.hpp`：实现互译函数；若互译逻辑复杂，可另建
   `Header/notation/translator_<name>.hpp`（命名空间 `omegay::translator`），
   并把互译函数声明到 `translator.hpp` 或直接引用。
2. `Expander.cpp`：
   - `#include` 对应的头文件；
   - 在 `kTranslatorTable[]` 末尾追加一条 `Translator` 条目（指定初始化，
     填齐六个字段）；
   - （若新增了独立头文件）在 `Expander.vcxproj` 的 `<ClInclude>` 登记。
3. `Docs/互译器规范.md` 与 `Docs/API.md`：补记该互译器的 id、方向与范围。
4. 本地验证（见第七节）。

> 注意：互译器不是记号，**不**需要 `IDR_DEF_*` 资源、`defs/*.txt` 定义文本或
> `build.ps1` 的 `$fileToId` 登记；改动头文件后直接全量重建即可
> （`build.ps1 -Mode rebuild`）。

## 六、命名约定

- 函数名：互译函数以互译方向命名，如 `identityTranslate`、`bmsV4ToUpms`；
  若逻辑复杂、拆出辅助函数，一律加族前缀（与记号约定一致，避免 ADL 歧义）。
- 头文件：`translator_<name>.hpp`，命名空间 `omegay::translator`。
- `id`：英文小写 + 连字符，语义化（如 `"identity"`、`"bms-v4-to-upms"`）。
- 文档：`Docs/互译器规范.md` 与 `Docs/API.md` 各维护一个互译器小节。

## 七、验证要求

新增互译器在登记前应至少完成：

1. **单元自检**：对若干已知序数的源记号表达式，断言互译结果解析为目标记号后
   序数不变（可用 golden 用例，形式同记号系列的 `tools/bml_golden`）。
2. **反向验证**：若目标记号已有展开器，可对"互译结果再展开"与"源记号直接展开"
   的序数做交叉核对；对不可逆互译，明确记录其方向性限制。
3. **错误路径**：空输入、乱码、非本记号文本、超范围输入必须返回错误文本且
   不崩溃、不抛异常。
4. **全量重建** 无新增编译警告；在互译器页面实测：选择该互译器 → 输入 →
   点击"互译" → 输出正确。

## 八、内置互译器

### 1. 恒等互译器（id: `identity`）

- `source`：任意 → `target`：相同（不改变）
- 直接原样返回输入，不做任何改写或校验。它用于验证互译器框架本身：
  选中它输入任意文本，点击"互译"后输出应与输入逐字节一致。
- 它是占位 / 调试 / 基线的互译器，后续真实互译器在其基础上按上述规范添加。
