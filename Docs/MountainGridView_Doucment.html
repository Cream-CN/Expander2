1. 概述

MountainGridView 是一个专用于展示序列山脉结构的 WinForms 控件。它包装了 DataGridView，默认启用虚拟模式（VirtualMode = true），使得即使面对十万乃至百万级别的单元格，也能保持流畅滚动与低内存占用。

它由两部分组成：

  • 后端 F# 模块 MountainDisplay
    • 位于 Expander_CS.Backend.Common 命名空间
    • 负责将序列或 Entry 列构建为 MountainTable 表格模型
    • 提供单元格文本访问、规模判断、CSV 导出等纯函数
  • 前端 C# 控件 MountainGridView
    • 位于 omegay 命名空间
    • 负责将 MountainTable 渲染到 DataGridView
    • 默认虚拟模式，按需提供单元格值
    • 提供拒绝展示、CSV 导出等 UI 行为

设计原则：

  • 后端只负责数据模型，不引用任何 UI 类型。
  • 前端只负责渲染，不实现任何数学展开逻辑。
  • 两侧通过 MountainTable 和纯函数接口通信。
  • 跨边界集合统一用 int[]，返回值避免 F# option。
NOTICE： 该控件专为“展示”设计，不包含任何记号展开或序列生成逻辑。所有数据必须由外部模块（如记号模块）计算后传入。
NOTICE： 前后端通信仅通过 MountainTable 和静态纯函数，避免 UI 类型污染后端，也避免后端逻辑渗入 UI。若需要扩展，请保持这一边界。

2. 文件位置与命名空间

后端 F# 文件：

Expander_CS.Backend/Common/MountainDisplay.fs
namespace Expander_CS.Backend.Common
module MountainDisplay

前端 C# 文件：

Expander_CS/UI/MountainGridView.cs
namespace omegay

项目引用：

Expander_CS (C# UI 项目)
    └── 项目引用 ──> Expander_CS.Backend (F# 类库)

C# 侧使用：
    using Expander_CS.Backend.Common;
    using omegay; // 如果 MountainGridView 与 Form1 不同命名空间
NOTICE： 项目引用需确保 F# 类库正确生成并引用到 C# 项目中，否则命名空间不可见。若编译报错“类型或命名空间不存在”，请先检查 F# 项目的目标框架与 C# 项目是否兼容。
警告： 不要将 MountainGridView.cs 放入 Expander_CS.Backend 项目。UI 控件必须位于 C# 项目中，否则无法引用 System.Windows.Forms。

3. 后端：MountainDisplay 模块

3.1 MountainCell 类型

F# 定义：

[<AllowNullLiteral>]
type MountainCell() =
    member val Value   : int       = 0   with get, set
    member val Row     : int array = [||] with get, set
    member val Cloumn  : int       = -1  with get, set
    member val Idx     : int       = 0   with get, set
    member val No      : int       = 0   with get, set
    member val Id      : int       = 0   with get, set

C# 可见形态：

public sealed class MountainCell
{
    public int   Value   { get; set; }
    public int[] Row     { get; set; }
    public int   Cloumn  { get; set; }
    public int   Idx     { get; set; }
    public int   No      { get; set; }
    public int   Id      { get; set; }
}

字段说明：

  • Value — 该单元格的值。
  • Row — 该单元格所在的行标签（int 数组）。
  • Cloumn — 该单元格所在的列索引（注意拼写为 Cloumn，沿用原代码）。
  • Idx — 该单元格在列内的序号。
  • No — 该单元格的编号（用于内部标识）。
  • Id — 该单元格的唯一编号。

注意：

  • MountainCell 仅保存展示所需的最小字段。
  • 它不包含 Parent / Head / Foot / Ref 等引用，避免循环引用。
  • 若需要完整 Entry 信息，请直接使用 Entry。
NOTICE： Cloumn 是原代码中的拼写错误（正确应为 Column），但为了保持 API 兼容性，文档与代码中均保留此拼写。若未来修复，需同时更新 F# 与 C# 两侧，并视为破坏性变更。
警告： MountainCell 被标记为 [<AllowNullLiteral>]，因此在 C# 中可以赋值为 null。在遍历 Columns 时务必进行 null 检查，否则会抛出 NullReferenceException。

3.2 MountainTable 类型

F# 定义：

type MountainTable() =
    member val Rows       : ResizeArray<int array>            = ResizeArray() with get
    member val Columns    : ResizeArray<ResizeArray<MountainCell>> = ResizeArray() with get
    member val MaxRows    : int = 0 with get, set
    member val MaxColumns : int = 0 with get, set
    member this.TotalCells : int
    member this.IsEmpty    : bool

C# 可见形态：

public sealed class MountainTable
{
    public List<int[]>           Rows       { get; }
    public List<List<MountainCell>> Columns { get; }
    public int  MaxRows    { get; set; }
    public int  MaxColumns { get; set; }
    public int  TotalCells { get; }
    public bool IsEmpty    { get; }
}

语义：

  • Rows[r] — 第 r 行的行标签。
  • Columns[r][c] — 第 r 行第 c 列的单元格；可能为 null，表示该位置无数据。
  • MaxRows — 总行数。
  • MaxColumns — 总列数。
  • TotalCells — MaxRows * MaxColumns。
  • IsEmpty — MaxRows = 0 或 MaxColumns = 0。

重要约定：

  • MountainTable 一旦构建完成，就不应再修改。
  • 它是只读视图；所有渲染都通过 MountainDisplay.getCellText 读取。
  • 单元格为 null 表示该位置在原始山脉中不存在对应 Entry。
警告： MountainTable 构建后应视为不可变。若在展示过程中修改其内部集合，将导致虚拟模式下的数据不一致甚至崩溃。
NOTICE： TotalCells 和 IsEmpty 是计算属性，每次访问都会重新计算。若在循环中频繁使用，建议先取出局部变量，避免不必要的开销。
严重 NOTICE： 不要手动设置 MaxRows 或 MaxColumns 为与 Columns 实际尺寸不一致的值。虚拟模式依赖这两个属性来分配行列，不一致会导致索引越界或空白行列。

3.3 构建函数

3.3.1 buildTable

F# 签名：

let buildTable (entries: ResizeArray<ResizeArray<Entry>>) : MountainTable

C# 可见形态：

public static MountainTable buildTable(List<List<Entry>> entries)

功能：从 Entry 列构建完整山脉表格。

参数：entries —— 每一列是一个 Entry 列表（从上到下）。列的顺序即山脉的从左到右顺序。

行为：

  • 收集所有出现过的 Row 标签，去重。
  • 按 Row 从大到小排序，作为表格的行顺序（山脉从上往下画）。
  • 对每个 (row, col) 位置，在对应列中查找 Row 匹配的 Entry。
  • 找到则填入 MountainCell，否则填 null。

使用场景：需要精确展示山脉结构（包括中间行）时。与记号模块配合，从 drawMountain 的输出构建表格。

NOTICE： 当多个 Entry 具有相同的 Row 标签但位于同一列时，只有最后一个会被保留（后者覆盖前者）。如果记号设计允许同列同标签重复，请确保 Entry 的唯一性或改用其他展示方式。
警告： 若 entries 为 null 或包含 null 的子列表，buildTable 的行为未定义（可能抛出 NullReferenceException）。调用前请确保所有输入非空。

3.3.2 buildFromSequence

F# 签名：

let buildFromSequence (seq: int[]) : MountainTable

C# 可见形态：

public static MountainTable buildFromSequence(int[] seq)

功能：从简单 int[] 序列构建山脉表格（简化版）。

参数：seq —— 整数序列。

行为：

  • 行标签固定为 [| 1 |]。
  • 每一列对应 seq 的一个元素。
  • 每列只有一个单元格，值为 seq[i]。
  • MaxRows = 1，MaxColumns = seq.Length。

使用场景：快速展示输入序列或输出序列。不需要完整山脉结构时的轻量展示。

NOTICE： buildFromSequence 生成的是单行表格，所有单元格的行标签都是 [| 1 |]。若序列元素需要区分行，请改用 buildTable。

3.3.3 两者的选择

  • buildTable — 精确展示，适合输出山脉。
  • buildFromSequence — 简化展示，适合输入序列或快速预览。
NOTICE： 两个构建函数都是纯函数，不修改输入参数，也不产生副作用。可以在任意线程调用，但返回的 MountainTable 一旦交给 UI 线程，就只应在 UI 线程读取。

3.4 规模判断

3.4.1 isTooLargeForDisplay

F# 签名：

let isTooLargeForDisplay
    (table: MountainTable)
    (maxCells: int)
    (maxRows: int)
    (maxCols: int) : bool

C# 可见形态：

public static bool isTooLargeForDisplay(
    MountainTable table,
    int maxCells,
    int maxRows,
    int maxCols)

功能：判断山脉是否超出展示上限。

返回：

  • true — 超出上限，应拒绝展示。
  • false — 在上限内，可以展示。

判断规则：table.TotalCells > maxCells || table.MaxRows > maxRows || table.MaxColumns > maxCols，任一条件成立即返回 true。

3.4.2 isTooLarge

F# 签名：

let isTooLarge (table: MountainTable) : bool

使用默认阈值：

DefaultMaxDisplayCells   = 2_000_000
DefaultMaxDisplayRows    = 2_000
DefaultMaxDisplayColumns = 2_000

3.4.3 默认阈值常量

MountainDisplay.DefaultMaxDisplayCells   = 2000000
MountainDisplay.DefaultMaxDisplayRows    = 2000
MountainDisplay.DefaultMaxDisplayColumns = 2000

注意：

  • 阈值只影响 UI 是否展示，不影响算法计算。
  • 提高阈值不会加快渲染，虚拟模式下渲染只取决于可见区域。
  • 阈值的意义是防止极端情况下构建表格本身消耗过多内存导致OOM。
严重 NOTICE： 默认阈值基于内存安全考虑。若将 MaxDisplayCells 提升至 1000 万以上，请确保运行环境有足够内存（≥1 GB 可用），否则可能导致 OutOfMemoryException 或界面无响应。
NOTICE： 即使表格被判定为“过大”并拒绝展示，MountainTable 本身仍会保留在内存中，以便通过 ExportToCsv 导出。若不需要导出，请在调用 ShowTable 后手动将 Table 置空（但控件未提供公开 setter，需通过 ResetToEmpty 清空）。
警告： isTooLargeForDisplay 的参数 maxCells、maxRows、maxCols 若传入负数，判断逻辑将全部返回 true（因为任何正数都大于负数）。请确保传入合理阈值。

3.5 单元格访问

3.5.1 getCellText

F# 签名：

let getCellText (table: MountainTable) (rowIdx: int) (colIdx: int) : string

C# 可见形态：

public static string getCellText(MountainTable table, int rowIdx, int colIdx)

功能：获取指定单元格的文本。

参数：

  • rowIdx — 数据行索引（0 起）。
  • colIdx — 数据列索引（0 起）；-1 表示行标签列。

返回：

  • 越界或 null 单元格返回空字符串 ""。
  • colIdx = -1 返回行标签（逗号连接）。
  • 其他情况返回单元格 Value 的字符串形式。

这是虚拟模式的核心接口。CellValueNeeded 事件中直接调用它。

NOTICE： getCellText 是唯一被 UI 层调用的数据访问函数，它必须保持极低开销。内部使用简单的数组索引和字符串转换，没有任何复杂逻辑，因此能胜任虚拟模式下的高频调用。
警告： 如果 table 为 null，getCellText 会抛出 ArgumentNullException。UI 层的 OnCellValueNeeded 已做 null 检查，但若在其他地方直接调用，请自行确保 table 非空。

3.5.2 getColumnHeader

F# 签名：

let getColumnHeader (table: MountainTable) (colIdx: int) : string

C# 可见形态：

public static string getColumnHeader(MountainTable table, int colIdx)

功能：获取列标题。

参数：colIdx — 数据列索引（0 起）；-1 表示行标签列。

返回：

  • colIdx < 0 — "Row"
  • 其他 — "Col0"、"Col1"、...

注意：列标题目前是占位符。若需要显示更友好的标题（如列号），可在 UI 层自行替换。

NOTICE： getColumnHeader 不检查 table 是否为 null，因为它不依赖表格内容。但为保持一致性，建议调用前仍确保 table 已正确初始化。

3.6 转换函数

3.6.1 toDataTable

F# 签名：

let toDataTable (table: MountainTable) : System.Data.DataTable

功能：将山脉表格转换为 DataTable。

注意：

  • 对超大表格会消耗大量内存，不推荐。
  • 默认虚拟模式下不需要此函数。
  • 仅用于非虚拟模式的备用展示或数据导出。
严重 NOTICE： toDataTable 会为每个单元格创建一个 DataRow，内存占用与单元格数成正比。对于 100 万单元格的表格，可能占用数百 MB 内存并导致长时间卡顿。除非确实需要 DataTable，否则请使用 toCsv。

3.6.2 toStringMatrix

F# 签名：

let toStringMatrix (table: MountainTable) : string[,]

功能：将山脉表格转换为二维字符串数组。

返回：矩阵尺寸为 [MaxRows + 1, MaxColumns + 1]。第 0 行是列标题，第 0 列是行标签。

NOTICE： toStringMatrix 返回的矩阵包含标题行和行标签列，因此维度比数据区域大 1。遍历时请注意索引偏移：数据从 [1,1] 开始。

3.6.3 toCsv

F# 签名：

let toCsv (table: MountainTable) : string

C# 可见形态：

public static string toCsv(MountainTable table)

功能：将山脉表格转换为 CSV 文本。

格式：

第一行:  Row,Col0,Col1,Col2,...
后续行:  行标签,值,值,值,...

特点：

  • 使用半角逗号分隔。
  • 行标签内部若含逗号，不会被转义（这是已知限制）。
  • 输出使用 UTF-8 编码保存时应无 BOM 问题（由调用方决定）。

使用场景：山脉过大被拒绝展示时，作为降级导出方案。用户手动导出完整数据。

NOTICE： 若行标签中包含逗号（例如 [1,2,3]），导出的 CSV 在 Excel 中可能错列。如需严格 CSV，建议在 toCsv 中增加转义逻辑。
警告： toCsv 不检查 table 是否为 null。若传入 null，将抛出 ArgumentNullException。调用前请确保表格有效。

3.7 统计信息

F# 签名：

let getStatistics (table: MountainTable) : string

C# 可见形态：

public static string getStatistics(MountainTable table)

功能：获取山脉表格的统计信息字符串。

返回格式："行数: R, 列数: C, 总单元格: T"

使用场景：拒绝展示时显示提示。调试或日志输出。

NOTICE： 统计信息中的“总单元格”是 MaxRows * MaxColumns，包含所有 null 单元格。若需要实际非空单元格数量，需自行遍历统计。

4. 前端：MountainGridView 控件

4.1 类定义

namespace omegay
{
    public class MountainGridView : DataGridView
    {
        // ...
    }
}

继承自 DataGridView，直接可用作 WinForms 控件。所有 DataGridView 原有属性、方法、事件仍然可用。

NOTICE： 虽然继承自 DataGridView，但 MountainGridView 重写了部分默认行为（如虚拟模式、行列管理）。不建议将 MountainGridView 与普通 DataGridView 混用同一套数据绑定逻辑。

4.2 构造函数行为

构造函数中设置的默认值：

VirtualMode                = true
ReadOnly                   = true
AllowUserToAddRows         = false
AllowUserToDeleteRows      = false
RowHeadersVisible          = false
ColumnHeadersVisible       = true
AutoSizeColumnsMode        = None
ScrollBars                 = Both
Font                       = Consolas, 9pt
AllowUserToResizeRows      = false
AllowUserToResizeColumns   = false
SelectionMode              = CellSelect
MultiSelect                = false
ColumnHeadersHeightSizeMode = DisableResizing
ColumnHeadersHeight        = 22

并注册事件：

CellValueNeeded += OnCellValueNeeded;

注意：

  • VirtualMode = true 是默认值。
  • 在调用 ShowTable 内部会临时关闭 VirtualMode 以调整行列，设置完成后再重新开启。
  • 用户不应手动修改 VirtualMode 属性。
警告： 不要将 DataSource 赋值给 MountainGridView，因为虚拟模式与数据绑定互斥，强行设置会导致 InvalidOperationException。
NOTICE： 构造函数中 RowHeadersVisible = false 是为了节省横向空间。若需要显示行号，请在创建后手动设置 RowHeadersVisible = true 并调整 RowHeadersWidth。
严重 NOTICE： 绝对不要手动将 VirtualMode 设置为 false 并同时保留 CellValueNeeded 订阅。这会导致事件不再触发，单元格全部为空，且可能引发不可预知的行为。

4.3 公开属性

4.3.1 MaxDisplayCells

  • 类型：int
  • 默认值：MountainDisplay.DefaultMaxDisplayCells (2000000)
  • 含义：最大展示单元格数。若 table.TotalCells 超过此值，拒绝展示。

4.3.2 MaxDisplayRows

  • 类型：int
  • 默认值：MountainDisplay.DefaultMaxDisplayRows (2000)
  • 含义：最大展示行数。

4.3.3 MaxDisplayColumns

  • 类型：int
  • 默认值：MountainDisplay.DefaultMaxDisplayColumns (2000)
  • 含义：最大展示列数。

4.3.4 Table

  • 类型：MountainTable
  • 只读：是
  • 含义：当前展示的山脉表格。未展示或已清空时为 null。

4.3.5 IsRejected

  • 类型：bool
  • 只读：是
  • 含义：当前山脉是否因超出上限被拒绝展示。true 表示表格中显示的是拒绝提示，而非山脉数据。
NOTICE： MaxDisplayCells、MaxDisplayRows、MaxDisplayColumns 可以在运行时修改。修改后需要重新调用 ShowTable 才能生效。
警告： 这三个属性仅影响 ShowTable 时的判断，不影响已经展示的表格。若展示后调低阈值，当前表格不会被自动隐藏。

4.4 公开方法

4.4.1 ShowTable

签名：public void ShowTable(MountainTable table)

功能：展示一个 MountainTable。

参数：table — 要展示的山脉表格；null 或空表则清空。

行为：

  • 若 table 为 null 或 IsEmpty，调用 ResetToEmpty()。
  • 若超出 MaxDisplayCells / MaxDisplayRows / MaxDisplayColumns，调用 ShowRejectedMessage()，显示统计信息和上限提示。
  • 否则正常展示：第一列为行标签列，冻结（Frozen = true）。后续每列对应 table 的一列。行数为 table.MaxRows。开启虚拟模式。
NOTICE： ShowTable 是幂等的。多次调用会完全替换当前内容，不会叠加。若传入相同的表格引用，也会重新设置行列并刷新。
警告： ShowTable 必须在 UI 线程调用。若在后台线程调用，会抛出 InvalidOperationException。若需要从后台线程更新，请使用 Invoke 或 BeginInvoke。

4.4.2 ShowSequence

签名：public void ShowSequence(int[] seq)

功能：直接从 int[] 序列展示山脉。

参数：seq — 整数序列。

等价于：ShowTable(MountainDisplay.buildFromSequence(seq));

适用场景：输入序列展示。输出序列展示（简化版山脉）。

NOTICE： ShowSequence 内部调用 buildFromSequence，生成的是单行表格。若序列很长（超过 MaxDisplayColumns），依然会被拒绝展示。

4.4.3 ResetToEmpty

签名：public void ResetToEmpty()

功能：清空展示，显示"（空）"。

行为：

  • 关闭虚拟模式。
  • 清空行列。
  • 添加一行"（空）"。
  • 重新开启虚拟模式。
  • IsRejected = false，Table = null。
NOTICE： ResetToEmpty 会将 Table 置为 null，因此之后调用 ExportToCsv 将返回空字符串。若需要保留导出能力，请先导出再重置。

4.4.4 ExportToCsv

签名：public string ExportToCsv()

功能：导出当前山脉为 CSV 文本。

返回：CSV 字符串；若 Table 为 null 返回空字符串。

内部调用：MountainDisplay.toCsv(_table)

注意：

  • 即使 IsRejected = true，只要 Table 不为 null，仍可导出完整数据。
  • 拒绝展示时 Table 仍被保留，就是为了支持导出。
NOTICE： ExportToCsv 不会修改控件状态，也不会弹出保存对话框。它只返回字符串，由调用方决定如何保存。
警告： 导出的 CSV 字符串可能非常大（例如 100 万单元格约几十 MB）。在 UI 线程拼接如此大的字符串可能导致界面短暂卡顿，建议在后台线程调用 MountainDisplay.toCsv 并自行处理保存。

4.5 事件

4.5.1 CellValueNeeded（内部处理）

签名：private void OnCellValueNeeded(object sender, DataGridViewCellValueEventArgs e)

功能：虚拟模式核心。按需提供单元格值。

行为：

if (_table == null || IsRejected)
{
    e.Value = "";
    return;
}

int r = e.RowIndex;
int c = e.ColumnIndex;

if (c == 0)
    e.Value = MountainDisplay.getCellText(_table, r, -1);
else
    e.Value = MountainDisplay.getCellText(_table, r, c - 1);

注意：

  • 此事件由控件内部处理，用户不应覆盖。
  • 如需自定义单元格显示，可继承 MountainGridView 并重写。
严重 NOTICE： 千万不要在外部订阅 CellValueNeeded 事件并覆盖内部处理逻辑。若必须自定义，请继承并确保调用基类实现，否则会导致单元格内容全部为空。
NOTICE： OnCellValueNeeded 在每次需要显示新单元格时被调用，频率很高。它内部只做简单判断和字符串转换，不执行任何耗时操作，这是虚拟模式流畅的关键。

4.6 内部实现说明

4.6.1 切换 VirtualMode 的时机

ShowTable 中需要先设置列和行数，此时必须临时关闭 VirtualMode。设置完成后再开启。这是 DataGridView 的常规做法。

4.6.2 行标签列冻结

Columns[0].Frozen = true，使行标签在横向滚动时保持可见。

4.6.3 拒绝展示时的表格布局

  • 只有一列 "Message"。
  • 宽度 400。
  • 显示 4 行提示。
  • 仍然保留 _table 引用以支持导出。

4.6.4 颜色方案

  • 行标签列：#EEE0E0 (浅红)
  • 数据列：#E0EEE0 (浅绿)
NOTICE： 颜色方案通过 DefaultCellStyle.BackColor 设置。若需要自定义颜色，请在 ShowTable 之后修改对应列的 DefaultCellStyle，不会影响虚拟模式的值获取。
警告： 在 ShowTable 内部临时关闭 VirtualMode 时，会触发 RowsAdded / ColumnsAdded 等事件。若外部订阅了这些事件，请确保处理逻辑不会在此时访问 CellValueNeeded 依赖的数据。

private void ExportCsv(MountainGridView dgv, string title)

    if (dgv.Table == null)

6. 虚拟模式原理与性能

6.1 为什么默认虚拟模式

传统的 DataGridView 绑定模式：

dgv.DataSource = dataTable;

会为每个单元格创建一个 DataGridViewCell 对象。对于 100000 个单元格，这意味着 100000 个对象，内存占用可达数十 MB，且初始化时间可能达到秒级。

虚拟模式：

dgv.VirtualMode = true;
dgv.CellValueNeeded += ...;

只创建可见区域内的单元格对象（通常几十到几百个），滚动时按需请求新值。内存占用恒定，初始化时间与单元格总数无关。

NOTICE： 虚拟模式的核心是“按需提供值”，因此 CellValueNeeded 必须尽可能快。任何耗时操作（如数据库查询、复杂计算）都不应放在该事件中，否则滚动会卡顿。

6.2 性能特征

操作 传统绑定模式 虚拟模式
1 万单元格 流畅 流畅
10 万单元格 明显卡顿 流畅
100 万单元格 可能无响应 流畅
内存占用 与单元格数成正比 与可见区域成正比
初始加载时间 与单元格数成正比 常数
滚动性能 受总单元格数影响 只受可见区域影响
NOTICE： 虚拟模式下，滚动性能只取决于可见区域和 CellValueNeeded 的执行速度，与总单元格数无关。因此，即使 100 万单元格，只要 getCellText 足够快，滚动依然流畅。

6.3 阈值配置建议

默认值已经足够宽松，适用于绝大多数用例：

MaxDisplayCells   = 2000000
MaxDisplayRows    = 2000
MaxDisplayColumns = 2000

如果确实需要展示更大山脉，可以按需调整：

dgvOutputMountain.MaxDisplayCells   = 10000000;
dgvOutputMountain.MaxDisplayRows    = 5000;
dgvOutputMountain.MaxDisplayColumns = 5000;

但不建议设得过大，因为构建 MountainTable 本身会消耗内存。一般来说，MountainTable 的内存占用约为：单元格数 × (MountainCell 对象头 + 字段)。每个 MountainCell 大约 50-80 字节（取决于 .NET 版本与对齐）。200 万单元格约 100-160 MB，这是可接受的。1000 万单元格约 500-800 MB，可能导致内存压力。

注意：阈值限制的是 MountainTable 的规模，不是 DataGridView 的渲染规模。DataGridView 在虚拟模式下渲染规模恒定。

严重 NOTICE： 调整阈值前请评估目标机器的内存。若 MountainTable 本身占用超过 800 MB，即使虚拟模式也无法避免构建阶段的内存峰值，可能导致进程崩溃。
NOTICE： 阈值判断在 ShowTable 中执行，若表格被拒绝展示，Table 属性仍然保留原始引用，以便导出。因此，即使不展示，内存占用依然存在。

7. 限制与注意事项

7.1 MountainCell 是简化模型

MountainCell 只保存 Value、Row、Cloumn、Idx、No、Id 六个字段。它不包含 Parent、Head、Foot、Ref 等引用。若需要在 UI 中显示这些信息，请直接使用 Entry，而不是 MountainTable。

7.2 列标题是占位符

getColumnHeader 返回 "Col0"、"Col1" 等。若需要显示更友好的标题，需要在 UI 层自行替换：

for (int i = 1; i < dgv.Columns.Count; i++)
    dgv.Columns[i].HeaderText = $"第 {i} 列";

7.3 CSV 不转义逗号

行标签内部若含逗号（例如 [1,2,3]），在 CSV 中不会被转义。这是已知限制。若需要严格 CSV，应在后端 toCsv 中增加转义逻辑。

7.4 不支持编辑

MountainGridView 是只读的。ReadOnly = true，且虚拟模式不支持编辑。若需要编辑功能，请另行实现。

7.5 虚拟模式与数据绑定互斥

DataGridView 的 VirtualMode 与 DataSource 互斥。MountainGridView 使用虚拟模式，因此不应设置 DataSource。若需要绑定模式，请直接使用 DataGridView 并调用 MountainDisplay.toDataTable。

7.6 行高固定

AllowUserToResizeRows = false，行高固定。若需要动态行高，需要重写 RowTemplate.Height 并处理 Resize 事件。

7.7 线程安全

MountainGridView 是 UI 控件，只能在 UI 线程创建和操作。MountainDisplay 是纯函数模块，无状态，可在任意线程调用。

警告： 虽然 MountainDisplay 可在任意线程调用，但返回的 MountainTable 一旦被 UI 线程引用，就不应在后台线程修改其内容。跨线程共享可变状态是未定义行为。
NOTICE： 若需要在后台线程构建 MountainTable，请确保构建完成后不再修改，然后通过 Invoke 将其传给 UI 线程的 ShowTable。

8. 扩展指南

8.1 自定义单元格显示

继承 MountainGridView 并重写 OnCellValueNeeded：

public class MyMountainGridView : MountainGridView

    }

NOTICE： 若将 OnCellValueNeeded 改为 protected virtual，请确保子类调用 base.OnCellValueNeeded(e)，否则内部数据绑定会失效。

8.2 添加列标题定制

dgvOutputMountain.RowHeadersVisible = true;
dgvOutputMountain.RowHeadersWidth = 40;

9. 常见问题

Q1: 为什么列标题是 Col0、Col1？
A1: 这是占位符。真实列号语义由具体记号决定，MountainDisplay 不假设列的含义。若需要自定义，在 UI 层修改 Columns[i].HeaderText。

Q2: 为什么单元格为空？
A2: 表示该 (行, 列) 位置在原始山脉中不存在对应 Entry。这是正常现象，山脉通常是稀疏的。

Q3: 为什么山脉被拒绝展示？
A3: 超出了 MaxDisplayCells / MaxDisplayRows / MaxDisplayColumns。可以调整这些属性，或使用 ExportToCsv 导出完整数据。

Q4: 导出 CSV 时中文乱码怎么办？
A4: 确保使用 UTF-8 编码写入。若用 Excel 打开，可能需要 UTF-8 BOM。可以将 Encoding.UTF8 改为 new UTF8Encoding(true)。

Q5: 可以同时展示多个山脉吗？
A5: 可以，创建多个 MountainGridView 实例即可。

Q6: 虚拟模式下可以编辑单元格吗？
A6: 不可以。虚拟模式不支持编辑。MountainGridView 是只读的。

Q7: 如何清空展示？
A7: 调用 ResetToEmpty()。

Q8: Table 属性有什么用？
A8: 用于导出 CSV 或检查当前展示的数据。即使 IsRejected = true，Table 仍然保留，以便导出。

Q9: 为什么 MountainCell 没有 Parent / Head / Foot / Ref？
A9: 为了避免循环引用和简化模型。展示只需要 Value 和 Row。若需要完整信息，请直接使用 Entry。

Q10: 支持哪些记号？
A10: MountainGridView 与记号无关。任何能产生 int[] 或 Entry 列的记号都可以使用它展示。

NOTICE： 若问题未在此列出，请先检查 MountainTable 是否正确构建，以及 ShowTable 是否在 UI 线程调用。多数异常源于跨线程操作或表格尺寸与行列数不一致。
警告： 不要尝试在 CellValueNeeded 事件中调用 ShowTable 或 ResetToEmpty，这会导致递归刷新和堆栈溢出。所有对控件的修改都应在事件外部进行。
